# notifyService توضیح ساده

این فایل برای توضیح `src/socket/notifyService.ts` نوشته شده است.

## این فایل چه کاری می‌کند؟

`notifyService` لایه‌ای است که سوکت را برای دریافت نوتیفیکیشن‌ها آماده می‌کند و وضعیت نوتیفیکیشن‌ها را در حافظه نگه می‌دارد.

به زبان ساده:

- سوکت را از `Socket.tsx` می‌گیرد.
- به رویدادهای `connect`، `disconnect` و `connect_error` گوش می‌دهد.
- رویدادهای نوتیفیکیشن را دریافت می‌کند.
- نوتیفیکیشن‌های دریافتی را داخل state داخلی ذخیره می‌کند.
- در صورت تغییر نقش کاربر، اتصال را با query جدید دوباره برقرار می‌کند.

## اجزای اصلی

### 1) نوع‌ها

در بالای فایل چند type تعریف شده:

- `NotifyType`
- `Noti`
- `Role`
- `Buckets`
- `State`

این typeها فقط برای مرتب بودن داده‌ها و جلوگیری از اشتباه در کد استفاده می‌شوند.

### 2) state داخلی

یک state محلی به نام `state` وجود دارد که موارد زیر را نگه می‌دارد:

- `connected`: آیا سوکت وصل است یا نه
- `role`: نقش فعلی کاربر
- `notis`: همه نوتیفیکیشن‌ها
- `needsRefresh`: آیا بعد از اتصال دوباره باید داده‌ها تازه شوند
- `liveUpdateCounter`: شمارنده‌ی رویدادهای زنده
- bucketهای جداگانه برای نوع‌های مختلف نوتیفیکیشن

### 3) listener ها

این فایل یک سیستم subscribe ساده دارد:

- `subscribe(listener)` برای ثبت شنونده
- `emit()` برای ارسال snapshot جدید به همه شنونده‌ها
- `getState()` برای گرفتن وضعیت فعلی

یعنی هر جایی از برنامه که به وضعیت نوتیفیکیشن نیاز داشته باشد، می‌تواند subscribe کند و با تغییر state آپدیت شود.

## جریان اتصال سوکت

### `startNotifyService()`

این تابع، سرویس را برای اولین بار روشن می‌کند.

کارهایی که انجام می‌دهد:

- نقش فعلی را از `localStorage` می‌خواند
- سوکت را از `getSocket()` می‌گیرد
- query سوکت را با نقش و userId آپدیت می‌کند
- event listenerها را bind می‌کند
- اگر لازم باشد سوکت را connect می‌کند

### `stopNotifyService()`

این تابع سرویس را خاموش می‌کند.

کارهایی که انجام می‌دهد:

- listenerها را remove می‌کند
- اگر `disconnect=true` باشد، سوکت را disconnect می‌کند

### `switchRoleInService()`

وقتی نقش کاربر عوض می‌شود از این تابع استفاده می‌شود.

کارهایی که انجام می‌دهد:

- نقش جدید را از `localStorage` می‌خواند
- اگر نقش عوض شده باشد، state را sync می‌کند
- اگر لازم باشد لیست نوتیفیکیشن‌ها را پاک می‌کند
- query سوکت را با نقش جدید به‌روزرسانی می‌کند
- اتصال را با تنظیمات جدید دوباره برقرار می‌کند

## رویدادهای سوکت

### `onConnect()`

وقتی سوکت وصل می‌شود:

- `state.connected = true`
- `state.needsRefresh = true`
- `emit()` صدا زده می‌شود

در نسخه فعلی یک `console.log` هم اضافه شده تا زمان connect را در کنسول ببینی.

### `onDisconnect()`

وقتی سوکت قطع می‌شود:

- `state.connected = false`
- `emit()` صدا زده می‌شود

### `onConnectError(err)`

اگر اتصال خطا بدهد، خطا در کنسول چاپ می‌شود.

## دریافت نوتیفیکیشن

### `onNotifyEvent(eventName, payload)`

این تابع قلب فایل است.

جریان کار:

1. اگر `payload.type` نباشد، از `eventName` پر می‌شود.
2. اگر `recordStatus` برابر 0 نباشد، نوتیفیکیشن رد می‌شود.
3. با `toNoti()` payload به ساختار استاندارد `Noti` تبدیل می‌شود.
4. با `push()` داخل لیست مناسب ذخیره می‌شود.
5. `liveUpdateCounter` یک واحد زیاد می‌شود.
6. `emit()` اجرا می‌شود تا UI آپدیت شود.

## کمک‌کننده‌ها

### `toStrictRole()`

نقش را فقط به یکی از این دو مقدار تبدیل می‌کند:

- `admin`
- `user`

### `readRoleFromStorage()`

نقش را از `localStorage` می‌خواند.

### `toNoti(payload)`

داده خام سوکت را به ساختار داخلی `Noti` تبدیل می‌کند.

### `push(type, n)`

نوتیفیکیشن جدید را:

- به `state.notis`
- و به bucket مخصوص همان نوع

اضافه می‌کند.

## ارتباط با `Socket.tsx`

`notifyService` خودش سوکت نمی‌سازد.  
این فایل از این توابع استفاده می‌کند:

- `getSocket()`
- `connectIfNeeded()`
- `switchRole()`

پس `Socket.tsx` مسئول ساخت و مدیریت اولیه سوکت است و `notifyService` مسئول مصرف رویدادها و نگهداری state نوتیفیکیشن‌ها.

## خلاصه کوتاه

اگر خیلی ساده بخواهیم بگوییم:

- `Socket.tsx` سوکت را می‌سازد
- `notifyService.ts` به سوکت وصل می‌شود، رویدادها را می‌گیرد، و نوتیفیکیشن‌ها را مدیریت می‌کند
- `NotifyBootstrap.tsx` این سرویس را هنگام mount شدن برنامه شروع می‌کند

اگر خواستی، در قدم بعدی می‌توانم همین توضیح را به شکل:

- کامنت داخل خود فایل
- یا دیاگرام جریان
- یا نسخه خیلی کوتاه برای تیم

هم برات آماده کنم.
